# PLAN: `keep` and `drop` — taking things off the collection

Written 2026-08-08, at the end of a session that started with "spot checking
this stuff is depressing" and ended somewhere better. This is the design to
start the next session from. Nothing here is built yet.

## The problem, stated the way it actually feels

A 612-program disk offers everyone the same bad choice: take all of it, or
work out for yourself which pieces you want and how to get them. rdoggett's
words for the result — *"I don't want <whatever>, and now I don't know what to
delete!!? This is the feeling I always got when I was on Windows."*

The fix is not a better installer. **It is not an installer at all.** "Install"
means all-or-nothing, unknown extent, no way back — which is the dread itself.
The verb is `keep`: you run things in place from `/h0`, and when one earns its
place you keep it. Test drive, then take.

## What makes it cheap

Measured, not assumed:

- **268 of the 423 programs in `CMDS` and `CMDS/GAMES` need nothing but their
  own binary.** `keep ls` is one file copy.
- 41 more need only `/h0/sys/termcap`, which `SYS/login`'s `TERMCAP` already
  settles.
- Only **114** need real data files, and `DOC/DEPENDS` already lists which,
  generated by scanning the binaries.
- A starter set (`bash ls cat less vi_nocio wc grep sed cp mv rm make tar`) is
  **676 KB**. Six games is 440 KB. Nobody is short of room for this.

## Three kinds of user, one verb

| | wants | needs from us |
|---|---|---|
| #1 magpie | takes a few things, files the disk away | `keep`, then archive |
| #2 curator | keeps the whole collection as `/h0` forever | **nothing new** — works today |
| #3 test-driver | lives at #2 for weeks, promotes favourites to `/dd` | `keep`, repeatedly |

#3 is expected to be the common case and is the one the design serves. #2
already works: the `/h0` arrangement, `SYS/login`, `TERMCAP`, and a `PATH`.

## The commands

```
keep <name>...      copy each program and whatever DEPENDS says it needs
keep <category>     a whole category, named as DOC/CATEGORIES names it
keep -n <name>...   dry run -- print exactly what would be written, touch nothing
keep -a             everything, after printing the total size first
drop <name>...      remove exactly what keep wrote for those programs
kept                list what has been taken, and from which collection
```

## The receipt is what makes it safe

`keep` writes `/dd/SYS/kept`: one line per file — program, destination path,
byte size, CRC.

- `drop` removes **only** files listed there.
- `drop` **refuses to remove any file whose CRC has changed**, and says so
  instead. So `drop hack` cannot eat your playground, your saves or your high
  scores — by construction, not by care.
- `kept` answers "what did this put on my disk?", which is the question that
  the Windows feeling comes from never being able to ask.

## Where the files land — OPEN, and the one thing that could go badly

rdoggett: *"the namespacing would look like `/dd/CMDS/FREE/hack` not the other
way around. but hack is a game. `/dd/CMDS/GAMES/hack` or
`/dd/CMDS/FREE/GAMES/hack` … the 2nd seems righter, but ick. just ick."*

Agreed that it is ick, and the ick is a signal. **Proposed resolution: drop
the namespace entirely and get safety from refusal instead.** `keep` mirrors
the collection's own layout straight into the destination —
`/dd/CMDS/ls`, `/dd/CMDS/GAMES/hack` — and **never overwrites**: on collision
it refuses, names the file, and stops, so nobody's own `ls` is ever silently
replaced. `-f` forces, `--prefix=<dir>` is there for anyone who does want the
files kept apart.

That gets the tidy layout without the nesting, and puts the protection where
the actual risk is. **Needs rdoggett's sign-off before anything is written.**

## How it gets built

**Microware C, and that is settled.** An earlier part of this session wrongly
treated `cc` as unavailable. It is the project's established path —
`tools/rebuild/rebuild.sh` drives it, and 203 of the programs on this disk were
made with it. The distinction that was muddled:

- the **image build** must not need Microware, because it runs on GitHub
- that does **not** mean nothing may be *compiled* with Microware — binaries
  are committed, and CI never sees a compiler

Proven live this session, with the SDK at `~/Developer/os9/play/oskBoot`:

```
cc /h6/hi.c -qm=16k -n=hi -f=/h6/hi        ->  12,980-byte module
os9exec -r hi   (freeware disk, no cio)    ->  runs, prints, exits
```

`-qm` gives a trap-free binary — no `cio`, no `math`. So:

- `SRC/install/keep.c` (or similar), our own source, on the disk
- built with `cc -qm=16k -n=keep`, binary committed like every other module
- `check_disk` gains a rule that the shipped manifest matches the tree

`gcc` on the disk is **not** an option for this: it is starred, and a build
attempt returns `**** Can't install trap handler **** cio`. `as0`, `as1`,
`lnk`, `ar`, `make` and `tar` are all trap-free if assembly is ever wanted.
`tar` source is `SRC/eff_tar/tar.c`, one file, if adding a `-k` flag ever
looks easier than writing `keep`.

## The browser is the chooser

Agreed. Curses is declined deliberately: it is exactly where this disk's
programs already fail — `lander` and `tet` are broken for terminal reasons
right now — and a chooser that misdraws is worse than none.

Instead, `docs/index.html` grows checkboxes and a box at the foot reading
`keep bash ls cat hack rain` to copy out. Selection happens where it is
pleasant; the OS-9 side stays dumb and termcap-proof. A line-mode `keep -i`
asking `y/n` is a later option if wanted.

## The author stamp stays, and gets better

All fifteen stamped modules carry the same 64 bytes: `from the disk of Robert
Doggett`. Not a gallery of strangers — rdoggett's own builds, which is why they
stay. *"If I built it back in the late 80's and that's why it's here, it's kind
of an easter egg."*

New binaries we build should not be blanked either, but should say something
deliberate. Proposed, keeping the joke's shape:

```
>>>>>>>>>> from the disk of the OS-9 community <<<<<<<<<<
```

**Consequence to handle:** `check_disk.py` counts occurrences of `from the disk
of` and caps them at 15, so reusing that phrasing breaks the check. The fix is
stricter, not looser — assert the *set* of person-stamped modules is exactly
those fifteen by name, which still catches a genuinely new personal stamp.

`CLAUDE.md` is NOT in that list and could not be: it is gitignored
(`.gitignore` line 14), because people downloading the collection have no use
for it. It was edited in the same pass -- stale `/h0` counts, the note that
Microware's `cc` is available, the load-bearing `builtin cd`, the writable-data
rule -- and those edits live only in the working copy. Worth knowing before
trusting git history to hold the whole trail.

Removals worth being able to defend if asked: `joke` and `reagan` on
rdoggett's explicit instruction; `disk/.login` and `USR/ANON/.login` were the
previous owner's scripts with wrong paths and personal mail/spooler hosts, and
Microware's `shell` runs `.login` at login so they were live, not inert;
`GAMES/ADV/startup` was 333 bytes of captured terminal session, not a startup
file. All recoverable from git history.

## Open questions for the next session

1. **Placement** — the refusal-instead-of-namespace proposal above. Blocking.
2. Does `keep` copy game *state* (scores, saves) or only static data, leaving
   games to create their own? Leaning: static only, so a `keep` after a `drop`
   never resurrects an old scoreboard.
3. Should `kept` record the collection's version, so a future release can say
   what changed? Wants a version string on the disk, which there isn't yet.
4. `keep` needs `DOC/DEPENDS` at run time. Read it from `/h0`, or bake the
   manifest into the binary? Reading it is honest and lets DEPENDS stay
   generated; baking it makes `keep` self-contained on a `/dd` that no longer
   has the collection mounted.
