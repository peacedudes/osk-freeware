# 2026-08-23 — blarslib, and what it unlocked

Branch `release-pass-2026-08-21`. Nothing pushed. Eleven checks green.

## blarslib

rdoggett said yes, minus the Microware headers. In as
`SRC/blarslib` + `DEFS/blarsdefs` + `LIB/blarslib.l` (32 of its 36 objects).
Thirteen of its headers were byte identical to Microware's or near enough and
did NOT ship; `DEFS/blarsdefs` carries one-line forwards of our own instead.
Those forwards must include BY ABSOLUTE PATH — `<sgstat.h>` from inside
`blarsdefs/sgstat.h` finds itself, and cpp opens it until it runs out of paths.

Four objects are out: `stat.c` (wants `sys/types.h` to define `dev_t` as a
struct, and the overlay's is `SRC/COMPAT`'s, which deliberately does not),
`ftime.c`/`makenv.c`/`putenv.c` (`time_t`, hidden behind `#ifndef ctime` in the
SDK's `<time.h>`), `gethostname.c` (a quoted `-D` the OS-9 shell will not
carry).

## What it unlocked

  - **uucp_blars** — all five programs. `uuxqt` also needed `pw_giduid`, OS-9's
    single packed group.user id, which our `pwd.h` did not have and blarslib's
    `getpw.c` never set.
  - **uucpbb** — 21 of 24. Out: `login` (wants an `<os9.h>` nothing here has),
    `chown` and `cnvrtmail` (assign to `fd_own`, an ARRAY in this `<direct.h>` —
    a port written against a version where it was one number, and not something
    to guess at in a program that changes ownership).
  - **smail 2.5** — all four. `SRC/COMPAT/types.h` is new: the SDK's
    `<types.h>` stops at `u_char` and friends, so `off_t message;` in
    `deliver.c` failed as a declaration and reported as `message` undeclared
    forty lines later.
  - **SB-Prolog** — its makefile builds `builtin/` as a library first; naming
    those sources alongside the simulator's comes to the same thing.

## Not unlocked, and why

  - **macutils** — needs `struct stat` as blarslib declares it, and there is no
    way to give two trees a different `<sys/types.h>`: cpp will not search a
    `-V` directory for an include name with a directory in it. This was the
    argument for taking blarslib in the first place, and it did not hold.
  - **gtar** — everything else is in place now, including a generated
    `testpad.h`, but `cpp` bus-errors on `tar.c`. Same defect as `flex`:
    `notes/CPP-MACRO-CRASH.md`. Two victims now, not one.

## Where the build stands

**271 of 274 recipes build clean** (measured 2026-08-23, whole tree, after the
`COMPAT/types.h` change). The three are `ls` (gcc2), `pdraw` (X11) and `pep`
(the EPROM board's own library). Recipes went from 203 at the start of this
pass to 274.

## Two lessons, both paid for twice

**Do not put a fix in `SRC/COMPAT` when one tree needs it.** `smail`'s
`deliver.c` wants `off_t`; adding it to a new `COMPAT/types.h` looked tidier
than a define and broke `less`, which `#define`s `off_t` itself -- so
`typedef long off_t;` became `typedef long long;`. It is `-Doff_t=long` in
smail's recipe now, scoped to the one tree.

**Do not edit anything a build reads while it is running.** The full build
that caught the `less` regression then reported two more failures that were
only the tree changing underneath it. A run measures the state at the moment
each recipe is reached, not at the start.
