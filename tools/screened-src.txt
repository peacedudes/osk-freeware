# Files under disk/SRC that tools/screen_microware.py flags on a STRONG rule
# and that a person has read and accepted. One path per line.
#
# check_disk.py fails if a file not listed here flags strongly, so a newly
# imported source tree carrying Microware material is caught before release
# rather than after. Adding a line here is a decision: read the file, and say
# in a comment why it is all right.
#
# The rule that makes this necessary, learned 2026-08-21: `disk/SRC/msfm` was
# 21 files of OS-9 file-manager internals, byte-identical to EFFO forum disk
# 12, whose sibling `note.doc` -- one directory ABOVE the SRC/ that was taken
# -- carries Microware's proprietary-confidential notice. The notice did not
# travel with the source. msfm had already been refused once, as a module.
# Nobody had ever run the screen over disk/SRC.

# flex is GNU's, and the SDK ships its own build of the same flex, so the two
# share a generated header. Common ancestor, not a copy.
disk/SRC/flex/flexdef.h

# Two <stat.h> declaring the same OS-9 file-status interface. An interface a
# program must match to call the system at all; the SDK's is one expression
# of it, these are another.
disk/SRC/eff_make/stat.h
disk/SRC/lua/CLIENTS/LIB/OSK/stat.h

# (disk/SRC/hc_utils/sys.c was here. REMOVED 2026-08-22 on rdoggett's
# instruction -- "I don't want to ship sys.c". It was his own, it displayed
# OS-9 system information, and nothing on the disk was built from it.)

# Heike C. Zimmerer's, from the pd-ksh edition 11 OSK port. German comments
# throughout, and they call the documented F$Permit/F$Protect calls the SSM
# manual describes -- third-party code using a published interface. Read in
# full 2026-08-21. See tools/rebuild/pdksh/README.md.
disk/SRC/pdksh/OSK/SRC/ssmpermit.a
disk/SRC/pdksh/OSK/SRC/ssmprotect.a

# The FSF's own getopt.h, GPL, copyright Free Software Foundation. The SDK
# ships a copy of the same GNU file -- Microware shipped GNU tools too -- so
# the overlap is a common ancestor and runs the other way round. This is the
# screen's known blind spot: "matches the SDK" is not the same as "is
# Microware's", because the SDK contains third-party code as well.
disk/SRC/ed/getopt.h

# Same FSF getopt.h as SRC/ed -- GNU tar ships the same header.
disk/SRC/gtar/GNUTAR/getopt.h

# A declaration of `struct passwd` -- the interface a program must match to
# call the system at all, so overlap with the SDK's is unavoidable and means
# nothing. Matthias Rosenthal's, from EFFO forum disk 5; it carries the OS-9
# fields pw_prio and pw_xdir. disk/SRC/COMPAT/pwd.h is our own second
# expression of the same interface.
disk/SRC/passwd/pwd.h

# Third-party compatibility glue: defines O_RDONLY, O_WRONLY and friends in
# terms of OS-9's own S_IREAD/S_IWRITE. It overlaps the SDK's stat.h because
# it names the same constants, which is the entire point of the file.
disk/SRC/infoxpress/BNU/ELM_2.4/HDRS/osk.h

# The pd-ksh port's own UNIX-compatibility headers, restored 2026-08-21 after
# being refused earlier the same day on weaker evidence than it looked.
#
# Both matched a file under `play/oskBoot`, which is rdoggett's WORKING build
# overlay, not a pristine SDK. Neither `ioctl.h` nor `termio.h` exists in the
# pristine tree at all, and no copy in the overlay carries a Microware
# copyright or any ownership claim. They are the standard System V ioctl and
# termio definitions, which is why they overlap: any two expressions of that
# interface do.
#
# Finding this is what `provenance()` in screen_microware.py was added for --
# "matches the SDK" had been reported the same way whether the match was
# against Microware's own files or against ours sitting beside them.
disk/SRC/pdksh/OSK/DEFS/ioctl.h
disk/SRC/pdksh/OSK/DEFS/termios.h

# unc's own tables of OS-9 syscall MNEMONICS -- the strings "F$Fork",
# "I$Open" and the rest -- so the disassembler can name a trap in its
# output. The published names of the system calls, held in the author's own
# `systraps[]`/`iotraps[]` arrays; no Microware code, just the labels a
# 68000 OS-9 module's `os9` instructions decode to. ORIG/ is the byte copy.
disk/SRC/unc/os9traps.c
disk/SRC/unc/ORIG/os9traps.c

# os9lib's own interface, not Microware's. 469 bytes declaring the entry
# points of TOP Munich's library -- info_str, info_is_locked, info_lock,
# info_unlock, info_change, info_signal, info_kill -- whose implementation is
# Ocker's info.c in that same library. It flags only because a copy sits in
# the SDK's DEFS/os9lib, which is where somebody installed TOP's library on
# the machine the SDK came from. The identical file already ships here as
# DEFS/os9lib/info.h; this copy sits beside uustat.c because naming the whole
# of DEFS/os9lib on the include path drags in its <stat.h> and collides.
disk/SRC/uustat/info.h
