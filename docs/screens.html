A program that cannot find its trap handler stops at once with

    **** Can't install trap handler ****

That is the message to recognise.  It is not a broken program, and on this
disk you should never see it -- if you do, the five modules have been removed
or the execution directory is not this disk's CMDS.

The list was MEASURED, by running every program on a disk with the five
modules taken away and matching that message.  It was never derived from
looking for the string `cio` inside a binary: that proxy is wrong in both
directions, and this collection has the scars to prove it -- `vi_nocio`
contains the string and does not need the module, while `cyberwar`, `gnuchess`
and `g` lack it and do.

FIRST: YOU MAY NOT NEED THIS AT ALL -----------------------------------

If you mount this collection as /dd -- the recommended arrangement, and
what DOC/README-RUNNING is about -- then nothing needs keeping.  Every
program is already where it expects to be, and 258 of them read data
from /dd that is right here.  Run them in place and be done.

`keep' is for the other case: you ALREADY RUN OS-9, /dd is YOUR system,
and this collection is mounted alongside as another drive.  Then a
program that reads /dd/GAMES/adv/glorkz will look on your disk and not
find it.  `keep' is what puts it there -- the program, and the files it
reads, in the places it looks for them.

That is the whole job: make a program that expects the collection at /dd
work on a /dd that is not the collection.

This program allows you to interactively solve cryptogram puzzles, or to simply
filter the input to the standard output IF the output has been redirected.  The
input can be pre-encoded or I can encode it for you.  If I encode it, I will be
able to tell you when you have correctly solved the puzzle.

Command-line options:
        -u      force all input to Upper-case.
        -e      Encode the input stream with a random cypher.
        -r      encode using a simpler, rot-based random cypher.  For a
                specific rotation, include a number from 1 to 26, e.g.:  -r13.
        -cSTR   encode using the Code STR as the encryption cypher.
        -gSTR   initialize the Guessed letters to STR.
        -n      include No brace-commands when saving or piping.
        FILE    read input from one or more FILEs instead of stdin.
        -i      output the Interactive commands.
        -h      output this Help list.
        -       the null option can be used to avoid an empty command tail.

Examples:
        fortune -l | crypto -r
        crypto -eu puzzles
        crypto -n -gzyxwvutsrqponmlkjihgfedcba code.file >result.file

netpbm

A real netpbm pipeline: pgmramp makes a greyscale ramp, pgmtopbm dithers it to a bitmap, pbmtoascii renders that as text. The gradient is visible in the density of the characters.

os9$ P=/dd/CMDS/NETPBM

os9$ $P/pgmramp -lr 48 12 > /dd/tmp/r.pgm
os9$ $P/pgmtopbm $P/../../tmp/r.pgm > /dd/tmp/r.pbm
os9$ $P/pnmfile /dd/tmp/r.pgm /dd/tmp/r.pbm
/dd/tmp/r.pgm:  PGM raw, 48 by 12  maxval 255
/dd/tmp/r.pbm:  PBM raw, 48 by 12
os9$ $P/pbmtoascii /dd/tmp/r.pbm

netpbm-convert

A netpbm session at the shell: a ramp made, cut down with pnmcut, and identified at each step.

os9$ P=/dd/CMDS/NETPBM

os9$ $P/pgmramp -lr 32 8 > /dd/tmp/s.pgm
os9$ $P/pnmcut 0 0 16 4 /dd/tmp/s.pgm > /dd/tmp/c.pgm
os9$ $P/pnmtile 64 16 /dd/tmp/s.pgm > /dd/tmp/t.pgm
os9$ $P/pnmfile /dd/tmp/s.pgm /dd/tmp/c.pgm /dd/tmp/t.pgm
/dd/tmp/s.pgm:  PGM raw, 32 by 8  maxval 255
/dd/tmp/c.pgm:  PGM raw, 16 by 4  maxval 255
/dd/tmp/t.pgm:  PGM raw, 64 by 16  maxval 255
os9$
