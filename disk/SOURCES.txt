SOURCES -- where each program came from, and on what terms==========================================================Provenance and licence notes for the OS-9/68K community software on thisdisk.  DOC/INDEX says what each program is; DOC/ORIGINS names the archive itcame out of; this file records the terms it arrived under.  CMDS/         The commands themselves (see DOC/INDEX)  CMDS/archives/  The original .lzh archives these were unpacked from.                Several also contain full C source (ed, elvis, grep).  DOC/          Per-package documentation -- man pages, .doc files, port                notes, and the GPL COPYING files.  See DOC/README.  SYS/          System files: termcap, motd  DEFS/         C header files -- THIRD-PARTY COLLECTIONS ONLY, no Microware                headers are here: auxlib, ncurses, os9lib, os9unix, GCC2, gdbm,                p2c and a UNIX compatibility layer.WHAT ON THIS DISK WE WROTE OURSELVES  A handful of system files are normally supplied by Microware.  None of  theirs is here; these were written for this collection, and they are  the only files on the disk that are ours rather than the community's:    SYS/errmsg    240 error descriptions, 000:000 to 000:255, including 67                  for BASIC09.  The numbers and mnemonics (S$Abort, E$BMID)                  are OS-9's own; the explanatory prose is ours.    SYS/termcap   converted from macOS xterm-256color terminfo -- it says so                  in its first line.  SYS/TERM holds the archive's own                  terminal descriptions and is NOT ours.    SYS/startup   the boot script os9exec runs    SYS/login     hands bash a working environment; see the file    SYS/profile   and profile.ksh -- shell startup, bash and ksh    SYS/password  su, tester and anon, for someone who is not us    SYS/motd      one line    readme, DOC/INDEX, DOC/ORIGINS, DOC/CATEGORIES, DOC/DEPENDS,    DOC/EFFO-INFO and this file -- the collection's own apparatus.  Five COMMANDS are also our builds rather than archive binaries: cat, wc,  basename and dirname, rebuilt with the gcc2 toolchain against os9lib  because every archived build of them needs cio, and ls, our repaired  build of GNU fileutils 3.13.  Everything else under CMDS came out of an  archive.Running it: os9exec is the kernel, and this disk becomes /dd --    OS9DISK=/absolute/path/to/this/dir  os9exec /dd/CMDS/sh(NOTE: a leading "./" in OS9DISK is a known os9exec bug -- modules load butevery file open fails.  Use an absolute path, or a bare name.)Microware's `shell` and `csl` are not here.  sh requires no Microwaremodule at all -- it is a statically linked, cio-free build, verified byrunning this disk standalone with no shell/csl/cio/math present anywhereon it.LAYOUT OF CMDS (reorganised 2026-07-13, everything re-tested from scratch)  CMDS/           67 commands, EVERY ONE verified to run with no Microware                  module present at all. Both were minimally reproduced and cleared.  - dfa.c preprocesses fine when cpp is run from the shell, and faults when    cc forks it with an identical command line.  compapi.c faults either way.Two earlier bisections of compapi.c both gave false answers and were thrownout: truncating mid-function leaves an unclosed brace, and truncating at abrace boundary can still leave an unclosed #ifdef.  Either alone faults cpp,so neither bisection was measuring the real trigger.  The cause is stillopen.Consequences, and neither costs us anything:  ocompress  not shipped.  It is a port of compress, and compress and compr             are already on this disk from other sources.  flex       SHIPPED -- the binary EFFO distributed, which is trap-free and             verified end to end (see DOC/flex/README-FLEX).  Only rebuilding             flex from its own source is blocked.
