				CRON DOCUMENTATION	Cron runs in the background and executes commands atpre-determined times and dates.  Cron is a system utility and only oneCron process may exist on the system.	Cron gets its instructions from a file called Crontab which isfound in the current directory when cron is first activated.  Crontabconsists of lines that have execution times and commands.  There are sixfields in each line, the first five specify a time, and the last fieldis the command to execute.	The time fields are ordered as minutes, hours, day of the month,month, and day of the week; the fields are separated by spaces or tabs. Allowable values for each field are as follows:	minutes			: 0-59,	hours			: 0-23,	day of month	: 1-31,	month			: 1-12,	day of week		: 0-6 (where sunday is 0).Furthermore, multiple values can be specified by separating them withcommas, or ranges can be specified with an intervening hyphen.  Finally,a wild-card time value can be specified with an asterisk (*).	The command field is a command line to be passed to the shell. Carriage returns can be embedded in the command line with a percent (%)sign.  A carriage return at the end of the line is assumed.  The commandline up to the first carriage return is passed to the shell, theremainder of the line is passed as standard input.Example crontab file :0 10 * * * calendar >/term0,15,30,45 * * * * atrun0 0 15 2 * dir0 3 * * 1 build monday%its monday%time for another work week%hooray0 4 1-7,15-21 * 2 syscheck >/h0/sys/syslog0 9 * * 1-5 echo "good morning master" >/termThis file will run a program called 'calendar' to /term every day at 10am,run the atrun program every 15 minutes of each day, run dir at midnighton February 15th, build a file called 'monday' every monday morning at3am, run a program called 'syscheck' the 1st and 3rd tuesdays of each month,and will send a message to /term every weekday at 9am.	Cron loads the crontab file into memory when cron is executed,so crontab may be edited at will.  Cron will check the crontabinformation every minute, but the information in memory will not reflectany changes since cron was invoked.  However, cron may be informed ofchanges with the -r option.	Since cron runs in the background, you can communicate with itby invoking cron from the command line with an option.  The latestinvocation of cron will send a message to the master cron, and thenterminate.  Attempts to invoke multiple crons that run in the backgroundcontinuously will return an error.  Cron options are :	-r : re-read the crontab file	-k : terminate	If for some reason cron misses a minute, it will attempt toexecute any commands that should have been executed the next time itawakens.  Cron cannot be forced to check for commands to be executed.
